## Changes since the previous source pin

Only **EIP-8038** changed among the 25 previously tracked files. The update clarifies:

- write costs also apply when the written leaf is newly created;
- `CREATE_ACCESS` already includes account access and write charges, which must not be
  charged again separately for creation;
- delegation installation's access charges are included in its authorization base cost,
  while resolving a delegation uses ordinary cold/warm access;
- clearing and then setting a slot to any nonzero value reverses the clearing refund;
- the access-list cost comparison concerns access gas, not calldata-floor charges.

The parameter values and charging formulas are unchanged. The snapshot and checksum were
refreshed. Existing REVM EIP-8038 constant/relationship tests pass; this review does not
add Amsterdam gas rules to the Frame profile, which still rejects Amsterdam execution.

The six selected AA files and their inclusion decisions are unchanged: 8141 is Hegotá SFI;
7906, 8151, 8250, 8272 and 8298 are PFI. EIP-7997 remains Glamsterdam SFI. EIPs 7819 and
7851 remain Hegotá DFI and excluded.

## Implementation cross-check

| Specification | Findings |
|---|---|
| 8141 | Current nested fee/limit envelope, signature hashing, VERIFY static execution with the APPROVE exception, approval ordering, atomic rollback and receipts remain covered by the native tests. Full opcode-level state gas and public-mempool policy are still incomplete. |
| 8250 | Key sets, shared sequence, selectors, protocol storage and first-use state charges remain covered. The local profile accepts both scalar and keyed layouts; activation-boundary replacement/eviction and public-pool rules remain unimplemented. |
| 8272 | The tuple helper follows verifier-frame calldata and slot-number semantics. `RECENT_ROOT_CODE` remains TBD upstream; no canonical verifier execution is claimed. |
| 7906 | The selected spec still defines POST_TX state-diff assertions. The toolkit provides synthetic introspection fixtures; raw suffix execution, trace construction and execution-body rollback preserving validation/payment remain pending. |
| 8298 | `SETCODEFROM_OPCODE` remains TBD. Source tracking does not provide an executable instruction. |
| 8151 | Existing opt-in tests cover raw-code eligibility, gas/warmth, reset, replay and overrides. The runtime uses the local chain's raw code and does not follow the recovered account's delegation target. |
| 7997 | The helper and runtime are available. Anvil's installation is still independent of the activation fork and uses nonce zero rather than the prescribed activation nonce one. |
| 8037 / 8038 | Current source snapshots are retained, but complete frame-level integration is not implemented. Ordinary EVM fork support must not be read as support for the full Frame state-gas model. |
| vFrame / 712 / 1153 | EIP-712 covers its own ABI, gas budgets and fee caps. Osaka execution uses a dedicated DEFAULT caller and transient internal context. VERIFY remains STATICCALL. Gas reimbursement reserves a maximum, charges metered gas plus a settlement allowance and refunds unused funds. |

vFrame remains a contract harness: no native envelope, state gas, native ecRecover change,
POST_TX trace access, account-trie nonce behavior, or exact outer network-fee settlement.
External contracts' transient storage also survives between its frames, because ordinary
contracts cannot clear other contracts' transient slots. Native EIP-8141 clears transient
storage between frames. This distinction is now explicit in the
[vFrame guide](../../vframe/README.md#testing-boundaries).

The limitations guide previously described the VERIFY/APPROVE exception as unresolved.
That wording was stale: the current spec expressly grants it, and both implementations
already match it. No runtime change was needed for that question.
